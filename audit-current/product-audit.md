# ToolKnit 产品收敛审查（2026-08-09）

## 结论

ToolKnit 的工程基础和长代码分页能力已经可用，当前主要问题不是功能太少，而是产品同时承担“通用文件工具箱、开发者工具、AI 内容工具、资料库和算法学习系统”五种角色，导致核心价值被稀释。

建议将公开版本收敛为“算法代码整理、分享与复习的本地工作台”，以代码分享工作室为入口，把错题、笔记和 FSRS 复习串入同一条闭环；PDF、图片和开发小工具保留为二级工具包，实验功能移出主导航。

## 本次检查路径

1. 操作台：可用，但首屏同时出现快速处理、剪贴板、笔记、错题、图片、代码、PDF、AI、固定工具和学习统计，首次用户难以判断主任务。
2. 代码分享空状态：整体清楚，编辑、预览、导出三块关系明确。
3. 80 行代码分页：自动识别 C/C++ 并生成 3 页，证明核心差异点已经成立；预览容器停在页面中段，容易让用户误以为前几行丢失。
4. 偏好设置：选项数量克制，但语言、署名和行号藏在浮层中，缺少页面尺寸、每页行数、背景和高亮行等关键输出控制。
5. 文件处理中心：三阶段结构合理，但 PDF 顶层同时展示 9 个操作，配方名称在首次处理前出现，输出区按钮在当前宽度发生中文换行。
6. 实验室：四个卡片均不可执行，却占据一级导航；更适合放在 GitHub Roadmap 或 Discussions。

## 建议的信息架构

- 今日：最近代码、待复习题目、最近输出。
- 代码分享：粘贴/导入、分页、连续长图、标注、导出。
- 题目与错题：题目链接、题解、错误原因、代码版本、标签。
- 复习：FSRS 到期卡片和历史。
- 更多工具：PDF、图片、JSON、Diff、二维码等次要能力。
- 设置：保持底部入口，不占用内容导航。

剪贴板并入代码分享的输入方式；资料库、笔记和错题合并为题目资料；AI 改为题解页里的上下文动作；处理历史只作为最近输出和任务详情；实验室从产品导航移除。

## 最高优先级

1. 用一句话重新定义产品，并让首页主按钮直接进入代码分享。
2. 把“粘贴代码 → 多页/长图 → 复制 → 保存为题目/错题 → 到期复习”做成唯一主闭环。
3. 首层导航从当前 14 个路由收敛到 5 个产品入口。
4. README 首屏用一段真实 GIF 展示 80 行代码自动生成 3 张图与连续长图，不再先罗列通用功能。
5. 将 908、690、609 行的三个大型视图拆为可测试的面板组件和 composable，避免继续在单文件中横向增加功能。

## 验证范围

本次在 Vite 浏览器模式检查了主要界面与 80 行代码分页，并运行了测试：11 个测试文件、76 个测试全部通过。未在 Tauri 原生窗口中验证文件选择、系统剪贴板、PNG/PDF 实际落盘、快捷键完整性和屏幕阅读器行为。
